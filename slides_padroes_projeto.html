🔐 Padrão Singleton

Garante UMA única instância em toda a aplicação

  • Construtor privado
  • Método getInstance() sincronizado
  • Ponto de acesso global

SessionManager: Antes vs Depois

❌ ANTES - Múltiplas Instâncias
// Múltiplas instâncias GerenteDaTarefa g1 = new GerenteDaTarefa(); GerenteDaTarefa g2 = new GerenteDaTarefa(); // g1 != g2 ❌ // Inconsistências! Usuario user = null; try { user = g1.getUsuario(); } catch(Exception e) { // Erro: estado perdido }
✅ DEPOIS - Singleton
// UMA única instância SessionManager s1 = SessionManager.getInstance(); SessionManager s2 = SessionManager.getInstance(); // s1 == s2 ✓ (mesma instância) Usuario user = s1.getUsuarioLogado(); // Sempre consistente! // Thread-safe com synchronized

📋 Padrão Strategy

Define família de algoritmos intercambiáveis

  • Interfaces bem definidas
  • Múltiplas implementações
  • Sem muitos if-else
  • Fácil estender

Strategy: Antes vs Depois

❌ ANTES - If-Else
// Muitos condicionais if (tipo.equals("CRIAR")) { gerenteTarefa.criar(...); } else if (tipo.equals("ATUALIZAR")) { gerenteTarefa.atualizar(...); } else if (tipo.equals("DELETAR")) { gerenteTarefa.deletar(...); } // Difícil de estender // Violar Open/Closed
✅ DEPOIS - Strategy
// Interface polimórfica ITaskService service = serviceFactory.getService(tipo); service.criarTarefa(...); service.atualizarTarefa(...); service.deletarTarefa(...); // Fácil estender // Open/Closed respeitado // Novo tipo = nova implementação

⚡ Padrão Proxy/Decorator

Cache em camadas com Redis

  • Proxy: Controla acesso ao banco de dados
  • Decorator: Adiciona funcionalidade de cache
  • Redis: Armazenamento em memória

Proxy/Cache: Antes vs Depois

❌ ANTES - Sem Cache
// Sempre consulta BD public Tarefa findById(Long id) { return repository .findById(id) .orElseThrow(); // ❌ Latência alta // ❌ BD sobrecarregado // ❌ Múltiplas queries }
✅ DEPOIS - Com Cache
// Tenta cache primeiro public Tarefa findById(Long id) { Tarefa cached = redis.get("tarefa:" + id); if (cached != null) return cached; // ⚡ Rápido Tarefa real = repository.findById(id); redis.save(real, 3600); // TTL return real; // ✓ Latência reduzida }

Fluxo Cache-Aside

Requisição
↓
Verifica Redis?
├─ ✅ SIM → Retorna (CACHE HIT) ⚡
└─ ❌ NÃO → Consulta BD → Armazena Redis

Performance: 📦 Cache vs 🔍 BD = ~100x mais rápido

👁️ Padrão Observer

Notificação automática de mudanças de estado

  • MongoDB registra todas as operações
  • Auditoria completa (CRUD)
  • Conformidade com LGPD
  • Rastreabilidade total

Observer/Auditoria: Antes vs Depois

❌ ANTES - Sem Auditoria
// Sem registro de operações public void criar(Tarefa t) { repository.save(t); // Sem histórico // Sem rastreamento // Sem LGPD // Impossível auditar }
✅ DEPOIS - Com Observer
// Registra automaticamente public void criar(Tarefa t) { repository.save(t); // Observer notificado auditService .registrarCriacao(t); // ✓ Histórico completo // ✓ Rastreabilidade // ✓ LGPD compliant }

AuditService - Operações

  • 📝 registrarCriacao(): Log de novos registros
  • ✏️ registrarAtualizacao(): Histórico de mudanças
  • 🗑️ registrarDelecao(): Rastreamento de exclusões
  • 🔑 registrarLogin(): Controle de acesso
  • ❌ registrarErro(): Registro de exceções

📊 Padrão Repository

Abstração de dados com JPA

  • Independente de ORM
  • Fácil criar mocks para testes
  • Mudanças no BD isoladas
  • Reutilização de queries

📁 Estrutura de Pastas

❌ ANTES
src/ ├── models/ ├── service/ ├── persistence/ ├── ui/ └── util/ // Desorganizado // Difícil de navegar // Responsabilidades mistas
✅ DEPOIS
src/ ├── controller/ ├── entity/ ├── repository/ ├── service/ │ ├── impl/ │ ├── event/ │ └── util/ ├── log/ ├── exception/ └── ui/ // Bem organizado // Fácil de navegar // Responsabilidades claras

✅ SOLID Principles

  • S - Single Responsibility: Cada classe, uma responsabilidade
  • O - Open/Closed: Aberto para extensão, fechado para modificação
  • L - Liskov: Implementações respeitam contratos
  • I - Interface Segregation: Interfaces específicas
  • D - Dependency Inversion: Inversão via Spring

🔄 Fluxo: Criar Tarefa

1. Interface Gráfica → POST /tarefas
2. SessionManager.getInstance() [Singleton]
3. ITaskService.criarTarefa() [Strategy]
4. AuditService.registrarCriacao() [Observer]
5. TarefaRepository.save() [Repository]
6. CachedTarefaRepository.invalidarCache() [Proxy]

1. Interface Gráfica → GET /tarefas/{usuarioId}
2. ITaskService.listar() [Strategy]
3. CachedTarefaRepository.findByUsuario() [Proxy]
├─ 📦 CACHE HIT: Retorna Redis ⚡ (RÁPIDO)
├─ 🔍 CACHE MISS: Consulta PostgreSQL → Armazena
4. Serializa resposta
